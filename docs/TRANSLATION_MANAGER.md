# Менеджер перекладів · Quest + Gossip

1. Підготуйте чисті локальні ClassicUA і Spoken на ревізіях із
   [sources.lock.json](../sources.lock.json) за [CLI-посібником](CLI.uk.md).
2. Запустіть Review UI з кореня проєкту:

   ```bash
   uv sync --locked
   uv run --locked python tools/review_ui_server.py --classicua ../ClassicUA --spoken ../spoken-wow
   ```

3. Відкрийте [127.0.0.1:8765](http://127.0.0.1:8765/). Виберіть
   **Spoken_Quests_UA · Quest + Gossip**. Пошук знаходить ID, назви, NPC,
   перевірені англійські оригінали й доступні українські тексти.
4. Увімкніть **Не в ZIP**, щоб побачити також записи без перекладу. Натисніть
   назву, щоб переглянути контексти й українські варіанти. Для правок,
   схвалення, вирішення конфліктів та порівняння джерел перейдіть до
   **Розширеної перевірки**. Вона зберігає попередні робочі процеси та CLI.
5. Натисніть **Попередній перегляд**, щоб перевірити результат без заміни
   поточної бази чи ZIP. Потім натисніть **Переімпортувати Quest + Gossip**
   та підтвердьте. Після успішної збірки менеджер оновить таблицю.
6. За потреби встановіть приватний ZIP і перевірте вікна квестів і Gossip
   у Forever за [ігровим чеклістом](QUEST_LOCAL_TEST_BUILD.md).

## Як читати підсумок

- **У ZIP** означає, що запис представлений у останній успішній збірці з
  поточними ревізіями та відповідною SHA-256 сумою поточного ZIP.
- **Лише в базі** означає записаний імпорт, якого немає в цій збірці.
  Оцінка агента або наявність кандидата сама по собі не є імпортом.
- Стан зіставлення, стан українського перекладу й наявність у ZIP показуються
  окремо. Попередній збіг Quest для локального тесту може використовувати один
  спільний запис ClassicUA для обох фракцій. Схвалені людиною зіставлення
  мають окремий статус. Відхилене або відкладене зіставлення блокує
  повторний імпорт і включення події в нову збірку.
- **Конфлікти кандидатів** і **Кілька перевірених оригіналів** мають окремі
  лічильники та фільтри в меню **Показати**. В обох фільтрах працює пошук
  за ID, назвою й текстом. Стан **Неоднозначне зіставлення (усі причини)**
  охоплює обидві категорії.
- Якщо для події є кілька перевірених англійських оригіналів, відкрийте
  потрібний варіант у деталях. Посилання відкриває чергу з точним контекстом
  для незалежної перевірки. Подія з неоднозначним оригіналом виключається
  з локального ZIP, оскільки в ігровому вікні доступні лише ID квесту й етап.
- Зауваження агента доступні в деталях навіть для рядків у ZIP. У підсумку
  кожна оцінка рахується один раз, незалежно від кількості NPC, до яких
  застосовується спільний переклад. Збіги Gossip за обробленим текстом
  показуються окремо як непідтверджені підказки для перевірки в грі.
- Quest рахується за парою Quest ID + етап. У деталях можуть бути кілька
  підтверджених англійських варіантів одного етапу. Gossip у списку
  рахується за NPC + хешем + формулюванням, із додатковими записами для
  канонічних контекстів, які неможливо безпечно звести до NPC/hash.
  Підсумок ZIP окремо показує фізичні NPC/hash пари й унікальні
  common-хеші. Один common-хеш може покривати кілька рядків списку.
  Назви квестів у Gossip рахуються лише в детальному інвентарі архіву.
- Якщо ZIP відсутній, відрізняється від контрольної суми або джерела змінилися,
  менеджер явно повідомляє, що дійсної збірки немає.
- Конфлікт двох схвалених версій Gossip виключає лише конкретну пару NPC/hash.
  У цьому діалозі зберігається оригінал, а спільний переклад лишається доступним
  іншим NPC. Виключення обліковуються окремо від перекладів у ZIP.

## Почати з чистих тестових даних

Прапорець **Почати з чистих тестових даних** діє лише після явного підтвердження.
Він очищає шість SQLite-журналів цього модуля: Quest mapping і workbench,
Quest/Gossip manual review та Quest/Gossip machine import. Також очищає
Quest/Gossip translation memory, оцінки й імпорти агента з їх історією та
рішення й історію ручних виборів джерел цього модуля.

Знімки й кандидати провайдерів, попередні метадані успішних ZIP, legacy JSON,
джерела, конфігурація, шаблони аддонів і дані інших модулів зберігаються.
Заповнені заново журнали не підхоплюють старі JSON. Для зовнішніх знімків
після скидання знову потрібне окреме рішення людини.

Збірка відбувається на тимчасовій копії SQLite. Поточний ZIP і журнали
замінюються після успішної збірки. У разі звичайної помилки зміни відкочуються;
якщо інший процес змінив базу або ZIP, повторіть операцію зі свіжим станом.
Якщо старі докази більше не проходять перевірку цілісності, режим збереження
може зупинитися до збірки. Виправте докази у розширеній перевірці або
виберіть явно підтверджене скидання тестових даних.

Уніфікована дія використовує чинні машинні, ручні та агентські правила.
Машинний Quest-збіг не набуває Stage 3 схвалення. Агент виконує
детерміновані перевірки для придатних маршрутів без зовнішньої моделі.
Збірка залишається приватним локальним тестом.
