# Аудит зіставлень Gossip між Spoken і ClassicUA

## Ревізії та відтворення

| Джерело | Коміт | Роль |
| --- | --- | --- |
| Spoken 3.9.0 | `3c896874e27ec9e07d51a3578c0b9fa8545c9ac7` | Історична ревізія проєкту |
| Spoken 3.10.1 | `db5669b0a39815dd38568f0e871f4ced82bc9229` | Офіційний тег `spoken/v3.10.1`, версію підтверджено в TOC |
| ClassicUA 7.1.1 | `1770d208ad853d23d61105cf510d53804770d916` | Чиста закріплена ревізія, маніфест Camelot |

[Окремий маніфест аудиту](../config/gossip_audit_baselines.json) фіксує SHA-256 корпусу, псевдонімів і TOC. Для 3.10.1 достатньо окремого Git-репозиторію з отриманим комітом. Корпус і псевдоніми побайтово однакові в обох ревізіях Spoken. Порядок ClassicUA — `classic → sod → forever`. Наступний шар замінює лише надані ключі Gossip, а таблицю `!code` замінює повністю.

```sh
git init build/spoken-3.10.1
git -C build/spoken-3.10.1 fetch --depth=1 https://github.com/rusty-key/spoken-wow.git refs/tags/spoken/v3.10.1
uv sync --locked
uv run --locked python tools/gossip_mapping_audit.py --classicua build/pinned-ClassicUA --spoken-390 build/pinned-spoken --spoken-3101 build/spoken-3.10.1
```

Параметр `--zip dist/Spoken_Gossip_UA_Local_Test.zip` перевіряє контрольну суму наявного ZIP і рахує записи перекладів у ньому. Підсумок записується в `build/gossip-mapping-summary.json`, а приватні докази — у `build/gossip-mapping-evidence.json`. Докази містять англійські формулювання, індекси рядків корпусу, канонічні ID, ревізії, шляхи й номери рядків джерела та контрольні суми. Аудит читає Git-об’єкти й за потреби ZIP. Він не змінює SQLite або рішення користувача.

Аудит відтворив **2 382 / 7 429 (32,1%)**. Історичний метод допускає поле `text` за відсутності `originalText`. У цих ревізіях жодна пара не потребувала цього запасного варіанта. Після групування 170 рядків увійшли до вже наявних пар. У доказах залишилися всі канонічні ID Spoken, зокрема варіанти `g:<md5>:m` і `g:<md5>:f`. Числові хеші ClassicUA є ключами пошуку. У корпусі є 109 значень голосу, 274 рядки з позначкою статі гравця та 1 766 рядків, у яких `text` відрізняється від `originalText`.

Англійські коментарі відтворюють усі 427 хешів ClassicUA (375 Classic, 47 SoD і 5 Forever). Після застосування шарів залишаються 100 записів для конкретних NPC і 327 спільних. Для прямих збігів використовується 216 записів (3 для конкретних NPC і 213 спільних). Окремий підрахунок наявного локального ZIP також дав 216 записів (3 та 213). Усі 216 відповідають чинним ключам і контрольним сумам перекладів ClassicUA. Для 26 чинних динамічних шаблонів збережено окремі дані про походження.

## Пари без прямого збігу

| Перевірювана причина | Пари |
| --- | ---: |
| Нормалізоване поле `text` точно збігається з коментарем у відповідній області пошуку, а `originalText` відрізняється | 166 |
| Точний англійський збіг із ClassicUA Chat, без збігу Gossip у відповідній області | 8 |
| Точне формулювання Gossip є лише під іншим NPC ID | 4 |
| Жоден перевірений шлях не дав кандидата | 4 868 |
| Альтернативний оригінал того ж контексту, підтверджений псевдонімом Spoken | 0 |
| Збіг за динамічним шаблоном ClassicUA | 0 |
| Збіг після заміни артикля або крапки, доступний лише в потоці реплік гравця | 0 |
| Збіг з назвою заклинання у перевіреному глосарії | 1 |
| Відсутній оригінал, колізія числового хешу або неоднозначний тип NPC серед історичних пар | 0 |
| **Усього** | **5 047** |

166 збігів за `text` потребують підтвердження, що це формулювання показує клієнт. Spoken зберігає підготовлений текст для запису окремо від оригіналу. Артефакт Spoken містить 454 ключі псевдонімів для пов’язаних або об’єднаних записів, без числових BroadcastText ID чи причин для кожного зв’язку. У корпусі явних BroadcastText ID немає.

Пошук в інших родинах охоплює перевірені англійські коментарі `chat` у завантажених файлах, явні англійські ключі й поля наявного адаптера та словники `misc`, предметів і заклинань. Серед збігів `chat` можливі декларації, замінені наступним шаром. Глосарій охоплює ці терміни й перевірені назви об’єктів, зон, NPC і завдань. Рядки з глобальних змінних клієнта, англійські тексти, яких немає у вихідних записах, неекспортовані BroadcastText та фактичні пункти меню потребують окремого аудиту. Точний збіг тексту сам собою не підтверджує незалежне зіставлення Stage 3, озвучення чи роботу в клієнті. Див. [методику англійською](GOSSIP_MAPPING_AUDIT.md).

## Наступні PR

1. Додати до приватного редактора Gossip введення, вставлення й вибір перекладу за зразком редактора Quest. Спільний вибір для варіантів дозволяти лише за підтвердженого контексту. Зберегти всі попередні рішення, чернетки, дані про походження та імпорти в SQLite. Новий вибір позначати готовим до імпорту, зберігаючи значення попередніх схвалень і сумісність із CLI.
2. Винести інкрементальний імпорт готових записів Gossip в окрему команду, що перевіряє контрольну суму ZIP і зберігає решту записів. Окремо обробляти спільні та NPC-специфічні значення.
3. Окремо перевірити репліки гравця, контексти об’єктів, видимі формулювання й BroadcastText перед розширенням автоматичного повторного використання.
